# 1.7.21

## 这一版解决什么

上游 1.7.20 适配到 DSH Desktop 0.2.2-rc.3 为止；宿主 nightly 已经推到 **0.2.2-rc.5**，这一版把 rc.5 正式收进兼容矩阵，并交付了一套可复跑的离线漂移审计，证明"无需改锚"这件事而不是口头声明。

## 审计结论：rc.3 → rc.5 零漂移

对两份官方安装包（rc.3 / rc.5，sha512 校验通过后解包）跑逐补丁逐 pattern 比对：

- **[rc3] 与 [rc5] 逐行全等**：88 条补丁、每树 144 行 entries，status 与 occurrences 完全一致；diff 无新增漂移、无新增缺失。
- 22 条基线 finding 全部带证据归类为 `chained`（4 条：#46→#45、#84→#83、#88→#87、#53→#32，pattern 本身锚定其他补丁的产出）或 `layout-absent`（18 条：`*-nested` 键与桌面构建不 ship 的文件，rc.3 同样不存在）。
- 结论：**rc.5 对补丁系统与 rc.3 字节等价，1.7.20 的锚点无需任何改动**；本版只动兼容声明。

## 新增工具

- `scripts/drift-audit.mjs`：离线双树审计（复用插件自身 `patchStatusDetail` 判定 + `classifyChained` 证据链 + 多树均匀缺失降级），exit 0 = 干净；报告落 `docs/drift-2026-11-26.json/.md`。
- `scripts/verify-clean-baseline.mjs`：宿主树污染检测（`*.dshpurge.bak` sidecar 判定，restore 型 marker 不误报）。
- `lib/patch-match.mjs`：pattern 计数原语导出。

## 已知限制

- rc.5 结论来自**离线解包审计**（两份官方安装包），live 升级当天的真机验收仍需按 `docs/upgrade-day-rc5.md` runbook 走一遍「应用 → 重启 → selfcheck」。
- README 中的固定版本 TGZ 链接指向本 fork 的 v1.7.21 release；在 fork 发布同名 tag/资产前，请用本地 `npm pack` 产物安装。
